## 手机处理结果：未通过 CPU 目标

测量范围：同原始采样的读入、道路分类、编码、四片楼块简化、合成和校验；不含 SDK 截图、网络、真实 BLE、导航 UI 工作负载或 G。测量进程包含静态工具 UI，未隔离系统频率／调度，不应等同整款 App CPU 和峰值内存。

第一轮顺序为旧→新，后两个旧版区域出现约 2.5 倍 CPU 波动，因此又反序复测。反序新→旧的结果如下：

三个区域超过 10% 目标，不能以先前 Mac 结果替代手机验收。反序中最差绝对增量约 7.84ms／整块处理；这不是每帧绘制耗时。

## 圆屏绘制对照：通过

使用含最新 Wire 启动代码的隔离镜像 `run-qew4uipt`，比较冻结旧版 v1 绘制函数／地图与当前 v2 绘制函数／地图；同一坐标、缩放和画面范围。三主题 × 昼夜 × 0°／45°／90° × 两档缩放，共 36 组，每模式预热八次、正式 31 次，采用配对顺序和中位数。

- **36/36 在 10% 预算内，无失败组**；每组都有预期像素变化。
- 新版相对旧版稳定绘制耗时变化 **−2.77%～−2.10%**，约 23～25ms／次。
- 同源地图包 148124→148762 字节；不是实际 BLE 累计流量。
- scope 仅为两核驻留地图绘制和同步，不包括解压、传输、调色板准备、完整导航帧或 G。
- 完成后自动恢复并观察到稳定 .13 正常启动，再进行 .16 正常测试版烧录。

原始计时、状态与摘要在 `output/road-multitone/device-validation-20261104-215831/board-benchmark-*`。不能用此结果替代地图换块低帧率窗口、实际传输或 G 准确性测试。
