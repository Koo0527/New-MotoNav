- R1 的真实接线在宿主桩上复现五条失败断言，覆盖 idle 返回值、ISR 固定标记 incomplete、
  RTC 快照重复使用、非 TWDT 启动回读旧记录和阶段计时合并。R2 的六项接线测试与纯逻辑测试通过，
  包含 ISR 读取半更新记录、计时回绕、快照构建标识和 checksum 校验。
- `flush-ownership`、`heap-checks` 和栅格夹具通过。栅格工作与接收回归分别通过
  7,455,483 和 131 项。
- Arduino ESP32 3.3.10 开关两态构建通过。关闭版自报 `175c.16`，没有诊断符号或字符串。
  开启版的 ISR 和各级原子读取为对齐 32 位访问与内存屏障，未调用加锁原子辅助例程。
  RTC 快照位于 `0x50000200`。app 内嵌 ELF 哈希与归档 ELF 相同，merged 的 `0x10000` 切片与 app 相同。

## 真机

实读确认启动槽为 app0，原应用为 `2c267899…`。只写 `0x10000` 后，诊断版启动及
CPU0 idle hook 注册成功。iPhone 实读 MotoNav 0.16.0 Build 29。
USB、赛博朋克、快速刷屏开启、QSPI 40 MHz。用户目检首图数秒内实际显示。

导航中复现两次 `IDLE0` TWDT。两次启动均回读到 `flags=0` 的 RTC 快照。

| 事件 | Idle 未闭合间隔 | 最后一次 help 完成距快照 | 最后一次 flush 完成距快照 | 当前 polling_end 已耗时 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 5,013 ms | 64 ms | 46 ms | 26 ms |
| 2 | 5,012 ms | 49 ms | 30 ms | 18 ms |

首轮在设备时钟 67,423–69,470 ms 的同一空闲间隔内，idle 计数保持 59,479，
同时完成 78 个 help 作业、26 帧刷屏及 1,404 个 SPI 分片。两次超时的
`polling_end` 历史峰值均为 33 ms。选用导航帧间空闲窗口分支，保留 SPI 超时。
第一段 canary 栈指针为 `0x3fcb8380`，低于匹配 ELF 的 coredump 栈下界
`0x3fcb838c`，回溯经过 Flash coredump 写入。

第二次转储已读回，SHA256 `35278e13b12f02bf2c7c7db370bdcdc084f2beff7b3bfe0697f6c89ec104856e`。
诊断组提前结束，按实读镜像回退 `2c267899…` 并验证启动。USB 引起的工具复位单列。
手机 R2 记录有 746 条事件，20 次地图发送全部为 v2。用地图 ID 对齐手机 ACK 和板端 commit，
两次 TWDT 分别位于手机录制约 372.353 s、402.866 s，随后分别记录断连。

## 空闲窗口修复及实机对照

修复候选 `175c.16-cpu0fix-r1`，app `36e41316587231ae884fe3c58a823b3be8f38c5126f6fc4cdbc6cbb410cf86b4`，
ELF `c1629b89f1b7e69941b5f4fa1cd531bc5f8844300f7ea35f8d8a5fc69a8dd5ef`。
首帧之后每 250 ms 在下一帧前排空上一帧，持有 `flushDone` 阻塞 2 个 RTOS tick。
宿主回归用真实导航入口验证了首次出图、唤醒、时间回绕、单缓冲路径及双缓冲令牌顺序。
只把空闲窗口代码和行为测试应用到共享工作树，候选继续使用冻结源码及诊断探针。

只写 `0x10000`，回读启动指纹为 `175c.16-cpu0fix-r1`。板端观察到三轮持续渲染
约 58、53、64 秒，补测约 109 秒，合计约 284 秒。用户目检三轮首图基本秒开，
没有重启或 `NO DATA`。整段串口只有一次工具触发启动，最大闭合 idle 间隔
**295 ms**，摘要中的最大未闭合间隔 255 ms，三个丢包计数均为 0。
修复候选达到 1 秒 idle 门槛。各轮实际持续渲染时间分开记录。

## Build 29 受控重连

手机记录 3 个 `link-ready`。三次均发送 v2，用户目检均迅速恢复出图，
未见重启或 `NO DATA`。下表的“提交”要求手机 type 3 回执与板端 `RASTER commit` 匹配。

| 重连 | 地图包 | 确认结果 |
| --- | --- | --- |
| 1 | 43 | 发送到尾片，记录中无尾片响应、地图提交或 type 3 回执 |
| 2 | 45 | 已提交并收到 type 3 回执，距 link-ready 约 5.77 s |
| 3 | 46、47、48 | 46 回执超时并触发重试，录制结束前无新提交或 type 3 回执 |

三次实显均通过目检，新底图的提交和回执有一轮可完整核对。缺少提交与回执的
两轮待区分缓存恢复、连接中断和新底图传输的影响。圆屏保留修复候选，串口已释放。
电池场景和长测继续暂停。完整串口、手机记录、匹配制品和源码补丁见 `output/cpu0fix-20261107/`。
