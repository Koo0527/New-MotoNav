# G 短测矩阵 — Build 29 / 2c267899

目标：先验证 G 采样恢复与回放行为，不把长稳、精度或性能结论混入。当前圆屏固件为 `2c26789991ca82895192cdecc7eee73cc96caee9f5d64971be8abf9ec65ce91c`，但该固件在 Build 29 受控重连中曾出现 CPU0 `IDLE0`/`help` canary 重启；因此本轮必须遵守停止规则。

## 停止规则

任一短测出现以下任一情况：立即停止本组，不重试、不继续长测：

- `task_wdt` / `IDLE0` / `interrupt wdt`；
- `Stack canary watchpoint`、`Guru Meditation`、`Re-boot`；
- 串口首段被截断但出现 panic/backtrace。

保留首段串口日志、镜像哈希、匹配 ELF（当前候选 ELF `cd3456…`，若实际启动镜像不同则以对应 ELF 为准），交固件 agent。不得把 coredump 失败当作归因。

## 用例

### S1 FIFO 瞬态后连续采样

- 操作：进入 G 页并记录，保持约 1–2 分钟；观察 `#GD` 的 `lastfifo`、`stage`、`err/ovf` 和 `state`。
- 通过：出现半帧/瞬态后能在两次轮询或 100 ms 内恢复完整采样；不因瞬态直接进入 `state=5`；有效采样率连续。
- 失败：瞬态后长期 `WAITING`、`state=5` 或重启。
- 证据：串口首段、`#GD` 行、记录样本数/缺口。

### S2 丢样隐藏黄点与记录缺口

- 操作：制造一次 G 流中断（断连/停流），再恢复；检查实时黄点和历史详情。
- 通过：中断区间无旧黄点/旧值；记录中出现数据间断；恢复后新样本正常。
- 失败：缺口内显示旧值或跨缺口连线。
- 证据：屏幕/历史截图、记录 JSON 缺口行。

### S3 可信停车 3 秒自动恢复

- 操作：在可靠定位为 Stopped 的情况下保持静止约 3 秒，不点按钮、不退出 G 页。
- 通过：`state=1` 自动进入校准/运行姿态，恢复 G 输出；安装参数不被覆盖。
- 失败：一直 `WAITING` 或写入错误安装参数。
- 证据：`#GD` 前后状态、`#GQ`/安装参数。

### S4 Unknown 原页重试

- 操作：手机定位为 Unknown 时留在 G 页，点击“重新请求校准”，静止约 3 秒。
- 通过：无需退出页面即可进入校准并恢复；失败后可再次明确重试。
- 失败：按钮无效、页面卡死或误触发自动保存。
- 证据：`#GD`、按钮操作日志。

### S5 运动中禁止校准

- 操作：可靠 Moving 或明显运动时尝试入页/手动校准。
- 通过：不启动/不完成校准，不写安装参数；保持原参数。
- 失败：运动中被保存为新安装姿态。
- 证据：`#GD` 状态、`gmount2` 前后哈希/字段。

### S6 校准中断连保留原安装参数

- 操作：同连接启动手动校准，校准窗口中断开 BLE/流。
- 通过：候选取消，稳定窗口清空，原 `gmount2` 不变；重连后手动可重新开始。
- 失败：写入新参数或沿用旧稳定时间。
- 证据：串口/`#GD`、参数读取、重连后状态。
