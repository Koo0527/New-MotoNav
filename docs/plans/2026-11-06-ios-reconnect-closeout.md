# iOS 重连补图整改计划

实施 agent 按 `executing-plans` 分步完成。`3fdebd1` 是验收记录，现有实现与测试在共享工作树。以当前实现为基线，先让下面四个用例失败，再修生产路径。此轮验收范围为 iOS 宿主与可构建交付。固件与设备仍按暂停状态管理。

## 1. 连接窗口独立于地图状态

- [ ] 在 `MapFeeder` 保留现有重连窗口，由 `BleLink.onLinkReady`、首次认证、`isReady` 从真变假三个入口管理。断开时关闭发送门、取消本连接的窗口回调并保留最新底图。连接就绪时进入待认证，认证后启动一次 1 秒单调时钟窗口。延迟回调带连接代次，只能作用于创建它的当前连接。先更新已接受的 MPAL 版本，再判断能否放行。
- [ ] `sendChunk` 是底图统一发送门。必须已连接、已认证且窗口放行。当前连接收到 MPAL v2 即放行，1 秒到期使用已知最高能力，无 MPAL 走 v0。路线上下文、位置、转向、路线和 ghost 继续用现有入口和优先级。
- [ ] `resetChunk()`、切主题/图源、`resendAll()` 可以换待发底图、清旧地图发送状态，并通过原入口发送路线。它们保持本连接的认证状态、窗口和截止时间。窗口内即使当前没有底图也正常到期，稍后取到第一块时用已协商格式发送。

**回归**　未认证时模拟连接就绪、切图源、生产 `resetChunk`、新块到达，地图入队数为零。认证后窗口内换两块，只发最新块。覆盖 v2 是首个认证通知、先认证后 v1/v2、旧固件 1 秒后 v0，以及旧窗口回调在断线后与新连接交错。

## 2. 拒收、超时和重试共用一次预算

- [ ] 在 `BleLink` 按当前连接和 `mapReceipt.current.id` 处理 type 3 的 `N/K`。旧 ID 的 `N` 不得清除当前回执、吞吐计时或队列，也不得通知当前地图失败。`N`、最终回执超时和当前栅格 ATT 最终失败走同一个失败通知入口，保留已有的尾片探测次数。只清理失败包的剩余排队分片、回执和计时。保留已发出、正在等回调的 ATT 槽，以及路线、ghost、时钟等排队项。超时的定时回调须校验当前回执身份，防止旧回调处理新包。
- [ ] 把 `sendBulk` 改为 `@discardableResult -> Bool`，只有分片实际入队才返回 `true`。`MapFeeder` 同步用该结果更新发送时间、实际已发送的格式和负载。同一负载的第一次失败使用**相同 wire 字节和新的 8 位 ID**完整重试一次。新 ID 可排在旧 ATT 槽之后，旧回调释放槽后再写出。只在实际入队后更新地图 ID 并扣掉预算。未就绪、写入长度不足时保留一次待提交机会。旧 ID 的晚到 `K/N` 无权推进新 ID。
- [ ] Type 3 的重试由失败状态触发。`checkResend()` 可以继续提交尚未成功入队的首包或已排定的重试，不能仅因计时到期或新定位重新开预算。第二次失败后保留已确认底图并等待新块、连接或确实改变 wire 字节的能力更新。显式 `resendAll()` 可重新请求当前块，仍经过连接门。旧 type 1、路线和 ghost 的重发行为沿用原路径。

**回归**　使用生产 `sendBulk`、`K/N` 回调和真实 `BleBulkWriteQueue`/`BleMapReceipt`，仅桩化 CoreBluetooth I/O。覆盖：旧 N 到达时新回执仍在；当前 N 先于尾片 ATT 回调；超时时探测片仍在途；首次重试未能入队时预算保留；入队后旧 ATT 成功/失败都只释放槽；第二次 N/超时后连续定位零重试。核对重试总量、ID、实际写出顺序及非地图队列完整性。

## 3. 迟到 MPAL 接管正在发送的普通底图

- [ ] 将 `onRoadPaletteCapability()` 的处理顺序改为：先判连接窗口，再判本次实际编码是否改变，最后区分当前在途内容。窗口内 v2 到达可直接提交最新块，已有路线等排队项保留优先级。
- [ ] 窗口外，普通 v0 栅格仍排队或等待回执时，撤下旧地图余片及回执，保留在途 ATT 槽，用新 ID 把同一地图的 v2 负载入队。版本或字节未变时不提交。按实际已入队的 wire 版本去重，重复通知不耗预算，后续 v2 仍可替换已发送的 v1。入队成功才更新状态；若当前不能入队，保留最新版本待提交。
- [ ] 当前正在交付首个建筑包时，保留原保护。能力更新只标记待发，等该包收到 ACK 或本轮发送最终结束、在途槽释放后再评估。推进入口复用回执和 ATT 完成回调，暂停模拟定位也能推进。无关路线或时钟排队项继续原有传输。

**回归**　普通 v0 多片正在排队且有一笔在途，迟到 v2 后旧余片立即消失，新 ID 排队一次，等旧回调后写出。重复 v2 零发送。建筑首包在途仍保留，ACK 后即使没有下一次定位也能处理待发升级。

## 4. 宿主验收与交接

- [ ] 在现有 `ble-palette-lifecycle`、`map-source-mode` 测试中保留四条红绿证据：旧 N、早到 N、地图重置绕过窗口、在途 v0 无法切 v2。共享测试桩同步真实的入队返回值和在途语义。已有屏幕关闭及建筑包保护用例继续通过。
- [ ] 复跑 `ble-palette-lifecycle`、`map-source-mode`、`screenoff-maps`，按 iOS 工作流编译运行 `ble-bulk` 和 `ble-capability`。有 iPhone SDK 时从冻结集成源码做无签名 Release 构建，保留日志和产物标识。区分纯宿主通过、Release 构建通过、实际装机三种状态。
- [ ] 核对并保留现有地图、G、CI 工作树改动。若无法独立提交 iOS 修复，至少归档本轮差异、测试桩、未跟踪运行器和可复跑的集成源码快照，记录哪一份源码生成了候选。文档提交单独标明。后续仍按 CPU0 诊断、固件单独验收、iOS 受控重连组合验收的顺序推进。
