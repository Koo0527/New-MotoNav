# 道路分色接入记录

用户已看明波立交桥原生源图／当前／分色对照，并明确同意放宽“不新增地图材质编号”，复用现有16色地图格式，同步更新App和固件。颜色来自高德源图道路类别，不代表真实高度网络。原建筑平滑原型视觉门未通过，不随本支线发布。

## 冻结接口 v1

- 使用既有1200×1200、2m、0x8000自定义16色RLE；不启用EDGE、DENSE或退休的组合flags。
- 调色板槽14=0x4D4E，槽15=0x5201（无屋顶）或0x5211（有屋顶）。其他版本不按语义地图处理。RLE索引仅0…10，14/15不得实际使用。
- 索引0…7保留现有语义；8=原图橙色道路，9=原图黄色道路，10=原生边框保护像素，显示为主题地面色。10不能被建筑、延续旧楼块或加粗覆盖。
- 有屋顶标记必须与4…7实际存在一致。普通原版／卫星16色图保持原逻辑。
- 固件按当前实际主题和昼夜动态生成0…10颜色，不用手机包中固定颜色做游戏主题显示。GTA5日间8=RGB565(#C6CACA)，9=RGB565(#707A7A)，与已确认预览一致；VC保留黑色主路并以较浅深灰区分黄色路，赛博朋克使用两档青色。其他主题短暂复用时8/9退为普通道路色。
- 配对认证后的既有能力通知中增加 `CAP,MPAL,1`（10字节），并随 `#GB?` 的能力响应重发；不新增手机控制指令。旧固件没有此能力时，手机流式转回有效普通RLE：8/9/10→1，屋顶按BLD能力保留或清除。

## iOS接口约定

新增纯算法 `RoadPalette`（Foundation）：

```
isPacket(_ data: Data) -> Bool                 // 只判头部标记，不能递归调用RasterPacket.valid
hasRoofs(_ data: Data) -> Bool
classify(_ raw: [UInt32], w: Int, h: Int) -> [UInt8]
encode(frameId: Int, x0: Int, y0: Int, w: Int, h: Int, indices: [UInt8]) -> Data
encode(_ indices: [UInt8], like base: Data) -> Data
compactBase(_ data: Data) -> Data
forWire(_ data: Data, paletteSupported: Bool, buildingsSupported: Bool) -> Data
```

流式转码复用现有RLE，不在主线程解压1.44M数组。分类使用已验证的B原生薄边框及42°暖色分界；不连接缺失边线。先保护边框再做现有分类后处理，最终10保留保护信息。

## 工作与验收

1. 纯算法、包校验、楼块合成和旧端转码；0…7旧格式和普通16色图不变。
2. 固件解码／原子换图／旧楼块延续／关闭建筑／昼夜调色及能力通知；沿用4bit单次采样，不加入未达标AA。
3. App能力状态、发送、版本化缓存及当前区域渐进升级。新代材料缓存v3，旧材料v2及旧完整包只读回退；原4m楼块算法不变，可校验复用旧v2掩码。旧完整包不得把新处理任务标为完成。
4. 明波和五区回归；坏标记、越界索引、屋顶标记不一致、断连／锁屏／迟到回调、旧端、缓存损坏及开关清除；三主题昼夜生产预览。
5. 独立评审后按最高版本递增构建并统一交付。手机CPU/内存、包大小/ACK、圆屏绘制和G采样需记录，不能仅以离线预览宣称实测通过。

不清理用户离线包、配对、校准或轨迹。尚未实现真实全路网高度、被遮挡道路几何和新的建筑轮廓平滑。
